# 0004 — Headless CLI (`flowforge`)

- **Status:** Proposed
- **Milestone:** post-M3 (own track)
- **Author:** tonytan4ever
- **Depends on:** RFC 0001 (skills + `build_system_prompt`), the `ff-agent` turn loop
- **Tracking issue:** _CLI: headless FlowForge_

## 1. Summary & Goals

FlowForge should run **without a GUI**. The desktop app is just one *host* around
the `ff-agent` loop; a CLI is a second host that renders to a terminal. The win:

1. **Headless / cloud-desktop use** — run the agent on a remote box over SSH, no
   webview, no display. A single self-contained binary nails this.
2. **Testability** — the CLI drives the *real* agent loop, scriptable in CI without
   a browser.
3. **Composability** — `flowforge run "fix this bug" --json | jq` makes FlowForge a
   Unix citizen: pipeable, automatable.
4. **Architecture validation** — if the loop assembles and runs cleanly outside
   Tauri, the crate boundaries are honest.

Non-goals are listed in §8.

## 2. The reuse seam

`ff_agent::run_turn` takes only library types — nothing Tauri:

```rust
pub async fn run_turn(
    provider: &dyn Provider,      // ff-llm
    store: &MemoryStore,          // ff-memory
    tools: &ToolContext<'_>,      // ff-tools registry + jail root + approver
    session_id: &str,
    model: &str,
    system_prompt: Option<&str>,  // ff_agent::build_system_prompt(...)
    cancel: CancelToken,
    on_event: impl FnMut(AgentEvent),
) -> Result<Message, AgentError>
```

The CLI assembles the same dependencies the desktop's `AppState` does, supplies a
terminal `Approver`, and renders `AgentEvent`s to stdout/stderr. `AgentEvent`
(`Token | ToolCallStarted | ToolCallFinished | Done | Error`) maps cleanly to plain
text *or* a JSON line stream.

## 3. Layout

- New crate **`apps/cli`** (binary **`flowforge`**), an explicit workspace member
  (the `crates/*` glob is for libraries; apps live under `apps/`).
- The headless assembly (provider, skill set, tool registry, system prompt) lives
  in **one helper module** (`host.rs`) so it is the single place later milestones
  wire into — **M4 MCP tools** register into the same `ToolRegistry`, **M5 SQLite**
  swaps the `MemoryStore` behind the same API.
- The desktop is **not** refactored. The assembly is ~40 small lines against public
  `ff-*` APIs; duplicating it is cheaper than a premature `ff-host` crate. Extract
  one only if a third host or real drift appears (YAGNI).

### Approval

A `CliApprover` mirrors the desktop's `UiApprover`: a write/dangerous tool call
becomes a `y/N` prompt on the controlling TTY (and `ask_user`/#44 becomes a line
prompt). When stdin is **not** a terminal (piped / CI), a non-read-only call is
**denied**, never silently run — fail-loud. A non-interactive `--yes` / `--deny`
flag is a follow-on (§7, CLI.2).

### Cancellation

`tokio::signal::ctrl_c()` (portable across Unix and Windows) flips the
`CancelToken`, so Ctrl-C aborts a turn cooperatively the same way the desktop's
cancel button does.

## 4. Sessions are in-process today

`ff-memory::MemoryStore` is currently an **in-process** store (SQLite is M5). So:

- Phase 0 `run` creates a fresh session per invocation, runs one turn, exits.
- **Cross-invocation `sessions list` / resume is deferred to M5** (when the store is
  durable). Until then, multi-turn is delivered as an **interactive REPL** that
  keeps one `MemoryStore` alive for the life of the process (CLI.3) — useful and
  needs no persistence.

This is called out so we don't promise a feature the storage layer can't back yet.

## 5. Distribution — two channels from one crate

1. **Standalone release artifacts (primary).** A tag-triggered CI workflow builds
   `flowforge-<target-triple>` per platform and uploads to a GitHub Release. This
   serves the headless / cloud-desktop / CI audience, who must not download a
   ~100 MB GUI app to get a ~10 MB CLI. Rust binaries are self-contained (static
   stdlib; only the platform base libs are dynamically linked), so distribution is
   "hand someone the file."
2. **Desktop sidecar (bonus).** Tauri's `bundle.externalBin` copies the CLI into
   the app bundle so the GUI can shell out to the *real* agent and so installing
   the app ships the CLI at zero extra download. Caveat: a bundled sidecar is **not
   on the user's `PATH`** — exposing a `flowforge` command from the app needs an
   explicit symlink/installer step (documented, CLI.7).

## 6. Cross-platform scope

**Tier-1: macOS + Linux** (the real use case — a local Mac plus a Linux
cloud-desktop). **Windows: best-effort via WSL**, documented.

The CLI framing (clap + tokio + the `ff-*` crates) is fully portable; the actual
gate is the **`bash` tool**, which assumes a POSIX shell Windows lacks. Hardening
native Windows waits on demand, not speculation. Path handling uses `dirs`/portable
APIs (no hardcoded `~`); TTY detection uses `std::io::IsTerminal`; signals use the
portable `ctrl_c()` with any Unix-only extras behind `#[cfg(unix)]`.

CI already exercises the CLI through `cargo test --workspace` once it is a member;
only the *release* workflow (CLI.6) is net-new.

## 7. PR Breakdown

Phase 0 (the scaffold this RFC ships with) lands a compiling `apps/cli` whose
`flowforge run "..."` drives the real loop against the local LLM, plus
`flowforge skills list`. Everything else is additive and owned under the CLI epic.

| PR | Scope |
|----|-------|
| **Phase 0** | `apps/cli` crate + `host.rs` assembly + `CliApprover` + plain-text renderer + `run` + `skills list` (this RFC) |
| **CLI.1** | `--json` NDJSON event stream (final message + token/turn metrics on `Done`) |
| **CLI.2** | non-interactive approval flags (`--yes` / `--deny`); fail-loud in pipes |
| **CLI.3** | interactive REPL (multi-turn, one in-process session); durable `sessions list`/resume tracked with M5 |
| **CLI.4** | `--model` / `--skill` / `--pheno` flags (active-skill bodies + persona + model override) |
| **CLI.5** | docs, `--help` polish, exit-code contract, CONTRIBUTING note |
| **CLI.6** | `release.yml`: tag-triggered matrix build (macOS arm64 + Linux x86_64) → GitHub Release artifacts |
| **CLI.7** | Tauri sidecar (`externalBin`) + PATH-symlink caveat doc |

## 8. Non-Goals

- **Durable cross-invocation sessions** — waits on M5 SQLite (§4).
- **Native Windows** beyond WSL — gated on the `bash` tool + demand (§6).
- **Rich TUI** (panels, mouse) — the renderer stays line-oriented; stdout is the
  model's text, stderr is diagnostics, so pipes stay clean.
- **MCP tools in the CLI** — they arrive for free once M4's bridge registers into
  the shared `ToolRegistry` the `host.rs` helper builds; no CLI-specific work.
